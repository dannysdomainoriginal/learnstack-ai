MODELLING REQUIREMENTS SUMMARY
================================

1. INTRODUCTION TO MODELLING  
Modelling is a critical abstraction process used from the Requirements phase through Detailed Design. It serves as a visual description of system aspects to verify that all requirements are correctly captured before the coding phase begins. It is essential for both Verification and Validation.

2. LOGICAL VS. PHYSICAL MODELS  
- Models for User (Logical): Focuses on user capabilities and product perspectives, showing an external view of what the system should implement.
- Models for Design (Physical): Focuses on the architecture, the distribution of processes, and the physical hardware/software components.


3. USER STORIES  
A User Story is a narrative description of a requirement written from the perspective of the end user.
- Syntax: "As a <user category>, I want to <action description>, so that <reason>."
- Purpose: Used heavily in Agile methodologies to enable developers to work closely with system users.
- Examples: "As a Student, I want to unblock my registration so that I can update my course selection."


4. UNIFIED MODELLING LANGUAGE (UML)  
UML is a standardized general-purpose modelling language managed by the Object Management Group (OMG). It provides graphical notations to create visual models of software-intensive systems.

UML Diagram Categories:  
- Structural: Class, Object, Package, and Composite Structure diagrams.
- Behavioural: Activity, Use Case, State, and Sequence diagrams.
- Implementation: Component and Deployment diagrams.


5. USE CASE DIAGRAMS  
A Use Case diagram shows the functionality of a system using Actors and Goals.
- Boundary: A rectangular border defining the system's scope.
- Actors: Roles played by humans, hardware, or external systems (Primary vs. Secondary).
- Use Cases: Representations of goals the actors achieve on the system.
- Relationships: Association, Include, Extend, and Generalization.


6. MODELLING STRATEGY & TIPS  
- Naming: Always start Use Case names with a verb (e.g., "Create Account", "Transfer Credit").
- Scenarios: Use text descriptions to explain the sequence of steps for a specific interaction.
- Benefits: Use Case models are user-centric, identify internal/external factors, and reduce heavy text documentation.
